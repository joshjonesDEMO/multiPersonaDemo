The Single Story

Your platform team is building Project Apex — an internal Developer Velocity Dashboard ingesting signals from GitHub, CI/CD, and code review tools to surface bottlenecks and productivity trends. Greenfield, one sprint, four personas all involved. This is the demo story.

The pitch underneath the demo: The bottleneck in software delivery isn't speed inside any one phase — it's the context that gets lost at handoffs between phases. SA writes a doc, DE misinterprets a data contract, PO writes stories without code context, Dev implements the wrong thing. Cursor is the context layer that makes handoffs disappear.

System Architect

SDLC Phase: Plan + Design — "How do we build this? Architecture, services, API contracts."

Common Use Cases

Codebase archaeology

Inherit a large repo. Map service boundaries, coupling risks, and ownership without digging through stale docs.

Architecture Decision Records

Generate ADRs with tradeoffs analysis grounded in the actual codebase — not generic templates.

API contract generation

Produce OpenAPI specs that match existing route conventions — ready for DEs and devs to implement against.

Breaking change analysis

Map the blast radius of a proposed change across the entire repo before committing to it. Catch downstream surprises early.

Migration planning

Plan monolith extractions, DB migrations, or framework upgrades with full dependency context visible in the Agent.

Write transformation logic

Data quality tests

Debug production failures

Query optimization

Analyze slow dbt models for bottlenecks — get partitioning strategy, index recommendations, and rewritten SQL in the same conversation.

The next person @-references it directly in the Agents Window. Context doesn't get lost at handoffs because there are no handoffs — there's just one system.

Demo Tips

Open with the Cloud Agent

Start with the SA section — kick off the Cloud Agent audit immediately. While it runs, explain the story. Come back to the results at the end. Shows async work without making the audience wait.

Make the @-reference chain visible

Each persona @-references output from the previous one. Say it explicitly: "The DE is picking up right where the SA left off — no meeting, no Confluence, just context." Make the handoff moment visible.

PO persona surprises people

Use it to expand the story beyond engineering. "This isn't just for developers." A non-engineer doing meaningful work in the Agents Window changes how buyers think about ROI and seats.

Use a real demo repo

A small Python FastAPI + dbt + pytest project makes the @-references feel real. Even a minimal project with recognizable structure is better than lorem ipsum code.

Name the maturity stage

Frame the demo: "Most of your team is here — Code Assistant. We're going to show you what Agentic and Cloud Agents look like in practice." It gives execs a ladder to place themselves on.

Don't wait for Cloud Agents live

Fire off the Cloud Agent, say "I'll check back on that," and move on. The reveal at the end is the payoff. Matches how engineers actually work — async by design.

End on Bugbot

End with Bugbot + Cloud Agent results arriving together. It mirrors the maturity curve: Tab → Agents → Cloud Agents → automated quality gate. The audience sees the whole arc in one session.

The "between the boxes" close

Close with: "The bottleneck isn't writing faster — it's the context that disappears at every handoff. Cursor is the context layer." Let the demo evidence make the argument; you just name the pattern.
